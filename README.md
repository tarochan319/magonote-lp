# まごのて 需要検証LP

佐賀県伊万里市を対象とした需要検証用のランディングページ一式です。
要件定義：`C:\dev\設計書\magonote\需要検証用\要件定義_LP.md`

プロダクト本体（`magonote` Spring Boot プロジェクト）とは独立しています。依存関係はありません。

---

## 1. ファイル構成

```
magonote-lp/
├── index.html              LP本体（1枚完結）
├── assets/
│   ├── styles.css          デザイン。色・形は先頭の :root を書き換える
│   ├── app.js              アンケートフォーム。設問は SCHEMA を書き換える
│   └── img/
│       ├── dash_requester.png   依頼者ダッシュボード（セクション05）
│       └── dash_worker.png      働き手ダッシュボード（セクション08）
└── apps-script/
    └── Code.gs             回答の受信とスプレッドシートへの記録
```

## 2. 公開するまでの手順

### 2-1. 回答の保存先をつくる（先に必要）

1. Googleスプレッドシートを新規作成する（名前は任意。例：`まごのて需要検証_回答`）
2. そのシートで **拡張機能 → Apps Script** を開く
3. `apps-script/Code.gs` の中身をすべて貼り付けて保存する
4. **デプロイ → 新しいデプロイ → 種類を「ウェブアプリ」** にして、
   - 次のユーザーとして実行：**自分**
   - アクセスできるユーザー：**全員**
5. 発行された `https://script.google.com/macros/s/.../exec` をコピーする

> コードを修正したら、必ず「デプロイを管理」から**新しいバージョンを発行**してください。
> 発行しないと旧バージョンが動き続けます。

### 2-2. LPに接続先を書く

`assets/app.js` の先頭を書き換えます。

```js
var CONFIG = {
  ENDPOINT: 'https://script.google.com/macros/s/__DEPLOY_ID__/exec'  // ← ここ
};
```

### 2-3. 計測を有効にする（任意）

`index.html` のGA4ブロックのコメントを外し、`G-XXXXXXXXXX` を測定IDに置き換えます。
設定しなくてもページは動作しますが、訪問数とステップ別の離脱（F-MS-05, F-MS-06）が取れません。

### 2-4. 運営者情報を書く

`index.html` 末尾のプライバシーポリシー内に未記入箇所があります（赤字で表示されます）。

- `［運営者名をここに記載］`
- `［お問い合わせ用メールアドレスをここに記載］`

**この2つを埋めるまで公開しないでください。** 個人情報を取得するページとして不備があります。

### 2-5. Vercelに公開する

ビルド不要の静的サイトです。

```bash
npm i -g vercel
cd magonote-lp
vercel            # 初回。プロジェクト名を聞かれる
vercel --prod     # 本番公開
```

フレームワークのプリセットは **Other**、ビルドコマンドは空のままで構いません。

## 3. 広告からの流入を区別する

広告のリンクURLに `utm_` パラメータを付けると、スプレッドシートに記録されます（F-MS-07）。

```
https://＜公開URL＞/?utm_source=meta&utm_medium=cpc&utm_campaign=imari_req_nov
```

依頼側・働き手側や配信エリアごとに `utm_campaign` を分けておくと、後から流入元別に集計できます。

## 4. 集計のしかた

Apps Scriptエディタで関数 `buildSummary` を実行すると、「集計」シートに次が出力されます。

| 出力 | 対応要件 | 検証上の意味 |
|---|---|---|
| 回答区分の件数 | F-MS-01 | 依頼側／働き手側の比率 |
| 依頼側：料金の希望 | F-MS-02 | **H-01の一次判定。無償選択率** |
| 依頼側：チップ妥当額 | F-MS-03 | 価格感の分布 |
| 働き手側：無償受諾 | F-MS-04 | **H-01の供給側。無償を受けるか** |
| 居住地の分布 | — | エリア純度、供給の広がり |

### 読み方

依頼側の無償希望率と、働き手側の無償受諾率を**必ず突き合わせて**ください。

| 依頼側の無償希望 | 働き手側の無償受諾 | 判定 |
|---|---|---|
| 低い | — | チップ制が受け入れられている |
| 高い | 高い | 無償中心のモデルとして成立の余地あり |
| **高い** | **低い** | **制度設計の見直しが必要**（需給が噛み合わない） |

片側だけ見ていると3行目を見落とします。

## 5. スパム対策

広告を出すとbotからの送信が発生します。2段構えで弾いています（NF-LP-07）。

| 方式 | 内容 |
|---|---|
| honeypot | 画面外に隠した入力欄。自動入力されると記録せず捨てる |
| 送信時間 | 全問を4秒未満で終えた送信は記録せず捨てる |

いずれも**送信側には成功を返します**。弾かれたと分かるとbotが手口を変えるためです。
判定は Apps Script 側（`Code.gs` の doPost 冒頭）で行っています。クライアント側の判定は回避できるためです。

取りこぼしが多いようなら reCAPTCHA の追加を検討してください。

---

## 6. 撤退・検証終了時のデータ削除

LP上で次のとおり表明しています（NF-LP-06-1）。

> リリース中止の判断となった場合、いただいた情報等はすべて責任をもって削除いたします。

実施手順（NF-LP-09）：

1. Apps Scriptエディタで `purgePersonalData` を実行する
   → メールアドレス・UserAgent・参照元を消去し、統計部分だけ残す
2. 完全に消す場合は、**スプレッドシートをゴミ箱に入れたうえでゴミ箱からも削除**する
3. Apps Script の実行ログに残る情報も確認する
4. Vercelのデプロイを削除する

## 7. 修正するときの勘どころ

| やりたいこと | 触る場所 |
|---|---|
| 色・角丸・影・余白を変える | `assets/styles.css` 先頭の `:root` |
| 文言を変える | `index.html`（各セクションにコメントで要件IDを入れています） |
| 設問を増減する／選択肢を変える | `assets/app.js` の `SCHEMA` |
| 記録する列を変える | `apps-script/Code.gs` の `COLUMNS` と `doPost` の `row` |

### 変更してはいけない内容

要件定義 4-2 の記載禁止事項です。プロダクト本体で「実装しない」と確定済みのため、LPで訴求できません。

- 評価・レビューが見られるという表現（C-NG-01）
- チャット・メッセージでやりとりできるという表現（C-NG-02）
- 働き手側への収入見込み額（「月○万円稼げます」等）（C-NG-03）
- すでに稼働中であるという表現（C-NG-04）
- 実在しない利用実績・利用者の声（C-NG-05）

掲載しているダッシュボード画像も、これに合わせて**メッセージ・お気に入り・評価の項目を除去済み**です。差し替える際は同じ確認をしてください。
